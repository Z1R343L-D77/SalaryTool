# 当月薪水到手计算器

基于 Tauri 2 + Vue 3 + TypeScript 的桌面薪水计算器。输入基本工资、各类补贴和五险一金参数，按「累计预扣预缴」算出当月实发到手金额。

> 计算逻辑全部在前端 `src/core` 里，是纯函数并有单元测试；Rust 侧只负责创建窗口和写备份文件。

## 下载

不装开发环境也能用：到 [Releases](https://github.com/Z1R343L-D77/SalaryTool/releases) 下载 `SalaryTool-0.1.0.exe`，双击即开，单文件、免安装。

系统要求：Windows 10/11（WebView2 Runtime；Win11 自带，Win10 若缺失请先安装）。

## 一键启动

双击项目根目录的 **`start.bat`**：

- 自动检查 Node.js / 依赖 / Rust / MSVC，缺什么提示装什么
- 首次运行或源码有改动时编译原生 exe，之后直接秒开
- 启动的是独立的桌面程序，不经过浏览器
- 已在运行时不会重复开窗口，直接切换到已有窗口

| 命令 | 作用 |
| --- | --- |
| `start.bat` | 编译最新版本并启动桌面程序 |
| `start.bat -Dev` | 开发模式，带热更新窗口 |
| `start.bat -Rebuild` | 强制重新编译 |
| `start.bat -Installer` | 额外生成 `.msi` / 安装程序 |
| `start.bat -Install` | 自动安装缺失的 Rust 与 VS 生成工具（走国内镜像） |

也可以直接用 npm：

```bash
npm install
npm run dev        # 只跑浏览器版前端（仅调试界面用）
npm run tauri dev  # 开发模式桌面窗口
npm test           # 运行计算逻辑单测
npm run typecheck  # 类型检查
npm run tauri build # 打包安装包
```

编译出的 exe 位于 `src-tauri/target/release/salarytool.exe`。

## 计算口径

- **收入**：每个收入项单独标记「计入社保基数」「计入公积金基数」「计税」。两者分开是因为不少公司申报口径不同（社保按上年月平均工资，公积金只按基本工资）。
  - 基本工资：社保 + 公积金 + 计税
  - 补贴、餐补、全勤、加班：一般只计税，不计入任何基数
  - 报销类：两者都不计入
- **社保公积金**：社保基数和公积金基数**各自独立**，可分别选「按收入自动推算」或「手动填写」，各受当地上下限约束。这样能表达「社保按上年月平均工资、公积金只按基本工资」这类常见情况。
- **累计数据**两种来源：
  - 手填：直接填截至上月的累计收入 / 社保公积金 / 专项附加 / 已缴税额
  - 按月记录：逐月记录工资条上的实际数字，累计值自动加出来。中途才申报专项附加扣除、或某几个月收入不同，都能准确还原。
- **个税**：累计预扣预缴

  ```text
  累计应纳税所得额 = 累计收入 − 5000 × 月数 − 累计社保公积金 − 累计专项附加扣除 − 累计其他税前扣除
  本月应预扣 = 按年度税率表算出的累计税额 − 截至上月已预缴税额
  ```

  「月数」有两种口径，在「累计数据」页面切换（国家税务总局 2020 年第 13 号公告）：

  | 口径 | 适用场景 | 例子 |
  | --- | --- | --- |
  | **当年月份数**（默认） | 当年首次取得工资薪金 | 10 月发薪 → 扣 5000 × 10 = 50,000 |
  | **本单位月数** | 年内已有过工资收入（换工作） | 10 月发薪但在本单位第 4 月 → 扣 20,000 |

  这就是应届生入职当年常常一分个税都不缴的原因：减除费用从当年 1 月起算，
  年收入不到 6 万时累计应纳税所得额始终为负。**没有「应届生免税」这个政策**，
  是这条减除费用规则在起作用。

- **年终奖**：可选「单独计税」（奖金 ÷ 12 查月度税率表）或「并入综合所得」。
- **配置导入**：点顶栏「导入配置」，粘贴 JSON 或选择 `.json` 文件。示例见 [configs/](configs/)。

## 注意事项

- 各城市社保基数上下限和比例是**示例默认值**，每年 7 月各地会调整，请以当地人社局公布为准；界面上所有数字都可以改。
- 数据只存在本机 `localStorage`，不上传；「导出」在桌面版会弹出系统「另存为」对话框，可选任意位置。
- 大病医疗等按年度汇算的扣除项，按月计算时一般不填。
- `src-tauri/.cargo/config.toml` 把 crates.io 指向了 rsproxy 镜像（国内直连约 40 KB/s，镜像约 300 KB/s）。如果你的网络访问官方源更快，删掉这个文件即可。
- 编译时脚本会调用 VS 的 `vcvars64.bat` 设置 PATH/LIB/INCLUDE。否则 Git for Windows 自带的 GNU `link.exe` 会被 rustc 误用，报 `link: extra operand`；缺少 `LIB` 则会报 `LNK1181: 无法打开输入文件 kernel32.lib`。

## 加班费计算器

侧边栏「加班费」有独立的加班费计算器，与薪水计算互不影响：

| 项目 | 倍率 | 说明 |
| --- | --- | --- |
| 工作日 | 1.5 倍 | 延长工时 |
| 周末 | 2 倍 | 休息日加班，可用补休替代 |
| 节假日 | 3 倍 | 法定节假日，不能用补休替代 |

基数支持两种填法，随时切换（切换时会自动换算，数字不丢）：

- **按月薪折算**：小时工资 = 月薪 ÷ 21.75 ÷ 8（《劳动法》第 44 条口径）。默认跟随基本工资，也可手动改。
- **直接填时薪**：小时工资直接作为 1 倍基数，适合按小时签约的兼职 / 外包。

月计薪天数与每日标准工时在「计薪规则设置」里可改（默认 21.75 天、8 小时）。

### 工时录入：合计 / 日历

「工时录入」可以切换两种方式，切换不丢数据：

- **直接填合计**：分别填工作日 / 休息日 / 节假日三档小时数
- **按日历填写**：周一到周日逐天填加班时长，自动按日期判断档位并汇总

日历支持 2025–2045 年。每天右上角的小标签显示当前档位（班 / 休 / 假），点一下可以循环切换，
用于处理调休上班、非法定节假日放假这类情况；被手动改过的日期标签会高亮。

节假日识别范围：
- **自动识别**：元旦 1/1、劳动节 5/1–5/2、国庆 10/1–10/3（日期固定）
- **2025 年**：春节、清明、端午、中秋按国办公布的实际日期
- **其它年份的农历节日**（春节、清明、端午、中秋）日期每年不同，需要手动点标签设为「假」

日历顶部有「每天 N 小时」+「填工作日 / 填休息日」的批量按钮，一天一天填太慢时可以用。

### 与收入项联动

勾选「同步到收入项」后：

- 算出的加班费合计自动写入绑定的收入项（默认新建「加班费」，也可以选已有项）
- **加班费**和**加班补助**是两条独立收入项：前者由工时 × 倍率算出、随日历浮动；后者是公司另发的固定补贴，不参与联动
- 工时或基数一改，收入项金额立刻跟着变，工资合计、社保基数、个税全部重算
- 关闭联动时会把该项金额清零，避免留下陈旧数字

### 输入持久化

加班费的基数、工时、同步开关都保存在 `state.overtime` / `state.overtimeSync` 里，
和其他配置一起写进 localStorage。切换栏目、重启程序都不会丢。

## 导出路径

桌面版点「导出」会弹出系统「另存为」对话框，可以自由选择保存位置；浏览器版退回默认下载。

## 桌面原生行为屏蔽

`src/core/desktopGuards.ts` 在窗口最外层拦掉 WebView 自带的浏览器行为，避免破坏原生应用的感觉：

- 右键菜单
- Ctrl+R / F5 刷新、Ctrl+P 打印、Ctrl+S 另存为、Ctrl+O 打开文件、Ctrl+U 查看源码
- Ctrl+D 收藏、Ctrl+N/T 新窗口、Ctrl+W 关闭（关闭交给应用自己的按钮）
- Ctrl + / − / 0 页面缩放、F3 / F7 / F11 等功能键
- 拖拽文件到窗口触发的导航

输入框里的 Ctrl+A/C/V/X/Z/Y 正常可用。开发模式（`npm run dev`）保留开发者工具，方便调试；
打包后的 exe 在 tauri.conf.json 里设了 `devtools: false`，控制台也打不开。
